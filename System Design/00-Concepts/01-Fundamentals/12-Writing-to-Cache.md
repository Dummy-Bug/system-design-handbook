
## Cache Writing Strategies

Techniques used to write into the cache

- **Write Through Cache** - The data is written to cache first and then immediatley written to the DB or persistent storage. Using this DB and cache are always in sync hence supports strong consistency.So it is very good for safe read. the problem is very high latency on write operations.Mainly used in financial transaction etc or we have to store some configuration because configuration rarely ever gets changes but fetched a lot , one more example could be profile picture of a user , it does not change but whenever it does we have to make sure it is persisted.
- **Write Around Cache** - Data is only written to DB and later loaded in the cache.So cache is being byPassed by the writes so when read comes and data is not present inside the cache then it will fetch the data from DB and then respond .It is write efficient as we are only writing to the DB and keeps our cache less polluted because the entries that are not going to be very heavly read from the cache are not present unlike write through cache(it stores everything).But the con is first read will be slow.Stale reads also possible.e.g logs are dumped as soon as possible and not every log is required but if service is down then lot of teams might be fetchinh similar service or similar time period logs so those logs can stay in the cache and logs do not generally change.
- **Write Back Cache** - Data is written to the cache only and cache Asynchronously update the DB.So writes are faster and since async updates are their load DB is also less.only issue is data loss .so maybe logging in some kinda WAL file might be useful for durability.Very good for eventual consistency scenario as we are Reading from the DB but writing to the cache and we are okay with reading some old data.Remember write in DB is expensie but not so much in Redis etc.

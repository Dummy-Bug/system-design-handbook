# Thread names

> **Every thread in Java has some name.** It may be a **default name generated by the JVM**, or a **customised name provided explicitly by the programmer.**

## Getting and setting the name

```java
public final String getName()
public final void setName(String name)
```

**These are called on a `Thread` object.** To ask about the thread currently running, you need a handle on it first:

```java
Thread.currentThread()      // static method — returns the executing thread
```

```java
System.out.println(Thread.currentThread().getName());
```

Measured on JDK 25, from `main`:

```
main
```

> [!info] **`currentThread()` is static, and it has to be.** You are asking which thread is executing this line? — a question about the runtime, not about any particular `Thread` object you are holding. It is how a thread finds out about itself.

**The default names:** the main thread is called `main`, and threads you create are `Thread-0`, `Thread-1`, and so on in creation order.

# Thread priorities

> **Every thread in Java has some priority.** Default, generated by the JVM — or customised by the programmer.

## The valid range is 1 to 10

> [!important] **1 to 10, not 0 to 10.** It's not an array index. This is a favourite trick question, and the confusion comes from expecting a zero-based range.

**And 1 is the minimum, 10 is the maximum.** Which sounds obvious until you have to answer it under pressure.

> [!question]- **The two fathers at the village reading room.** His story for why 1 is low, 10 is high trips people up — and it is about ranks, not priorities.
>
> He goes to the panchayat building in his native village most mornings to read the newspaper. Two men, both around 45, are talking about their children.
>
> **The first is despondent.** My kid is not good. I spent a lot of money on his education — 70 or 80 thousand every year. And in the entrance exam he got a **terrible rank — 2,500**.
>
> Durga Sir looks up, startled: **2,500 is a good rank.**
>
> **The second is proud.** My kid is not like yours. Very prompt, very punctual. One night after dinner I just casually told him to read, and when I woke at 6 a.m. he was still reading. I feel proud — he got the **best performance**, rank **148,000**.
>
> Both men are illiterate. **They think a bigger number means a better result.**
>
> **The point:** ranks and priorities run in opposite directions, and mixing them up is exactly the mistake here. **A rank of 1 is best. A priority of 1 is worst.** These are not ranks.

## The constants

```java
Thread.MIN_PRIORITY     // 1
Thread.NORM_PRIORITY    // 5
Thread.MAX_PRIORITY     // 10
```

Confirmed on JDK 25: **1, 5, 10**.

> [!warning] **There is no `Thread.LOW_PRIORITY` or `Thread.HIGH_PRIORITY`.** The exam question lists them alongside the real ones:
>
> | | |
> |---|---|
> | `Thread.MIN_PRIORITY` | ✅ |
> | `Thread.NORM_PRIORITY` | ✅ |
> | `Thread.MAX_PRIORITY` | ✅ |
> | `Thread.LOW_PRIORITY` | ❌ **does not exist** |
> | `Thread.HIGH_PRIORITY` | ❌ **does not exist** |

## What priority is for

> **The thread scheduler will use priorities while allocating the processor. The thread which has the highest priority will get the chance first.**

> [!question]- **The traffic signal, and who gets waved through.** His illustration of scheduling by priority.
>
> Four roads meet at a signal. If everyone arriving is an ordinary citizen, the signal cycles clockwise or anticlockwise on some algorithm, and each road gets its slot in turn.
>
> **Now a state minister approaches on one road.** The traffic police switch the signal off and wave the minister through first — **higher priority than everyone waiting.**
>
> **Minister on one road, Chief Minister on another?** The CM goes first. If the police make the minister wait, he objects — I am the minister, why are you keeping me waiting? — and the answer is the CM is on the other road. **Oh, if the CM is there, then I will wait.**
>
> Add the **PM** on a third road, and the **President** on a fourth, and the order becomes: **President → PM → CM → Minister → everyone else.**
>
> **Replace the junction with a processor and the vehicles with threads**, and that is the thread scheduler. Threads with priorities 8, 6, 7 and 4 get the CPU in the order **8, 7, 6, 4**.

## Equal priorities

> **If two threads have the same priority, we can't expect the exact execution order — it depends on the thread scheduler.**

The scheduler may use round-robin, first-come-first-served, shortest-job-first — it is not specified.

# Getting and setting priority

```java
public final int getPriority()
public final void setPriority(int p)
```

**The allowed range is 1 to 10.** Anything else throws. Measured on JDK 25:

```
setPriority(7)  -> OK
setPriority(17) -> IllegalArgumentException
setPriority(0)  -> IllegalArgumentException
```

> [!info] **`IllegalArgumentException`, not a compile error.** `17` is a perfectly good `int`, so the compiler has no objection; the range check happens at runtime. **This is exactly the shape of question the exam likes** — the code compiles, and then throws.

# Default priority — and where it comes from

**The question he sets up carefully:**

> Is the default priority for **every** thread 5 — or only for the **main** thread?

The second sounds more precise, and precision usually wins. **It is the wrong answer.**

> **The default priority for the main thread is 5. For every other thread, the priority is INHERITED from its parent thread.**

Measured on JDK 25:

```
set main to 9, then start a child:   inside child: priority = 9
set main back to 5, then start a child: inside child: priority = 5
```

**The child's priority follows whatever the creating thread had at the time.** It is 5 only because `main` is 5 by default.

> [!important] **Parent thread and parent class are different things, and he stops to say so.**
>
> ```java
> class MyThread extends Thread { … }        // parent CLASS  = Thread
>
> public static void main(String[] args) {
>     MyThread t = new MyThread();           // parent THREAD = main
> }
> ```
>
> **The parent class** is what you extended. **The parent thread** is whichever thread executed the line that created this one. Priority is inherited from the **parent thread**, and it has nothing to do with the class hierarchy.

# The demo — and the twist

```java
class MyThread extends Thread {
    public void run() {
        for (int i = 0; i < 10; i++)
            System.out.println("child thread");
    }
}

class ThreadPriorityDemo {
    public static void main(String[] args) {
        MyThread t = new MyThread();
        t.setPriority(10);                 // ← line 1
        t.start();

        for (int i = 0; i < 10; i++)
            System.out.println("main thread");
    }
}
```

**The expectation:** child has priority 10, main has 5, so the child should run to completion first — ten `child thread` lines, then ten `main thread` lines.

**With line 1 commented out**, both threads are priority 5, so we can't expect the exact execution order or exact output.

## What actually happens

Measured on JDK 25, five consecutive runs with the child at priority 10:

```
run 1: mmmCCC
run 2: mmmCCC
run 3: mmmCCC
run 4: mmmCCC
run 5: mmmCCC
```

**The main thread finished first every single time**, despite having the lower priority.

> [!important] **He predicts this himself, and that is the honest framing.** He runs it live, gets mixed output instead of the expected order, and explains:
>
> > **Some platforms won't provide proper support for thread priorities.**
>
> If in your system you are not getting our discussed output, the problem is not with our program — it is the underlying system.
>
> **So the examinable rule and the observable behaviour differ, and both are worth knowing:** the rule is higher priority gets the processor first; the reality is that **priority is a hint, not a guarantee**, and on most platforms it barely registers.

> [!warning] **Never write code whose correctness depends on thread priorities.** Priority maps onto the operating system's own scheduling, which may collapse Java's ten levels into far fewer, or ignore them for ordinary user threads. **If you need thread A to finish before thread B, use `join()`** — that is the next session — **or a proper synchronisation tool. Not `setPriority`.**
>
> His joke about the fix is the giveaway: you can send a mail to Microsoft asking for a patch — but to send a mail, make sure you use a licensed version. There is no patch. This is how thread priorities work.

| **10** | **maximum** priority |

Ground rules

  • Hunt, don't wander — open the repo with exactly one question in hand. Reading with purpose is the whole method.
  • Own words only — never copy proprietary code, configs, or data out of company systems. Your notes capture your understanding, nothing else.
  • Say it aloud — if you can't explain it out loud, you don't have it yet.
  • End every "what" with a "why" — interviewers always follow with "why not X?" Pre-empt it in your notes.
  • Honesty beats bluffing — where the real answer is "we didn't handle that," note it and design the fix. That is a senior answer.
  • Read the nodes, not just the driver — the Jul 9 streaming trace first concluded "one event per turn" because it read only _graph_driver; the rich progress feed lives in the nodes' ctx.emit calls. Every layer can surprise you — verify at the layer where work happens.

Landmarks — start every dig here (known components, from prior verified traces)

  • API / streaming edge: chat.py, stream_guard.py — both return StreamingResponse(media_type="application/x-ndjson").
  • Streaming services: employee_streaming_service, onboarding_streaming_service — both drive graph.astream(..., stream_mode="updates") = node-level updates. No token streaming exists anywhere.
  • Graph nodes that narrate progress: conversation_node ("Understanding your query…"), employee_profile_node ("Looking up employee X…"), execution_runner_node (execution steps).
  • Driver: _graph_driver — emits InteractionRequiredEvent on __interrupt__ (HITL) and TerminalResponseEvent on terminal/error.
  • Event plumbing: two producers (nodes via ctx.emit + the driver) → one ctx.event_queue → consumer onboarding_event_stream drains it → NDJSON lines. Event types: ProgressEvent, PipelineStepEvent, InteractionRequiredEvent, TerminalResponseEvent.
  • Slow path: run_with_slow_warning — fires a warning event past ~10 s.
  • Extraction pipeline: cron_service repo (Go) — worker pool, Redis per-record locks, connection pooling.
  • Paytm: seller/service/paytm/PaytmService (yours, current OTP flow) vs. PaytmWebService (old web-credential flow, disabled — //@Service commented off).
  • UPI: phonepemobile package (yours). phonepe crypto — Checksum/Device generators — is Ankit's.

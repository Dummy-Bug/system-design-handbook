**Key insight — 1354 (Construct Target Array):** Work backwards from the max element. At the last step, the max = sum of everything else + original_value, so original = max − (total − max) = 2·max − total. But if max >> total, you'd do this many times — use mod to jump: steps = (max − 1) / (total − max). This is the `work-backwards-with-mod` trick in its purest form.

**Key insight — 1590 (Make Sum Divisible by P):** prefix[j] − prefix[i] ≡ 0 (mod P) means prefix[j] ≡ prefix[i] (mod P). Store last index for each residue; for each j, look up prefix[j] mod P in the map — this gives the shortest subarray to remove.

**Key insight — 2156 (Find Substring With Given Hash Value):** Computing hash left-to-right needs future characters. Compute right-to-left: hash(s[i..j]) = s[i] + s[i+1]×p + ... so you can peel off the leftmost character going backwards. Modular inverse of p allows dividing out the leading term.

**1131 (Max Absolute Value Expression)** is the cleanest trick: `|xi−xj| + |yi−yj| + |i−j|` expands into `max over 4 cases of (±xi ± yi ± i) − (±xj ± yj ± j)`. Track the running max of each of the 4 linear combinations, and the answer is max(max_combo − min_combo).

**899 (Orderly Queue):** The full proof that k ≥ 2 lets you sort is subtle — any adjacent swap is reachable by rotating to bring the pair to the front, swapping, then rotating back. So k ≥ 2 = bubble sort = full sort. k = 1 = you can only rotate, so check all n rotations for the lexicographic minimum.

**2681 (Power of Heroes)** is the most elegant contribution problem in this band. Sort the array. For each element at index i (as the maximum), every subsequence that has it as max and min any subset of elements before it contributes `nums[i]² × nums[j]` (where j < i). | [Number of Excellent Pairs](https://leetcode.com/problems/number-of-excellent-pairs/) | 2076 | identity: popcount(a AND b) + popcount(a OR b) = popcount(a) + popcount(b) — sort by popcount, binary search |

**2354 (Excellent Pairs)** has the cleanest identity: for any two integers a, b: `popcount(a AND b) + popcount(a OR b) = popcount(a) + popcount(b)`. This is because each bit that's 1 in both contributes 2 to the left (once in AND, once in OR) and 2 to the right. Each bit in exactly one contributes 1 to the left (OR only) and 1 to the right. So the condition `popcount(AND) + popcount(OR) ≥ k` reduces to `popcount(a) + popcount(b) ≥ k`. Sort by popcount, binary search for each element.

## Drill plan for this band

**Priority 1 — highest contest ROI:**
- **CONTRIBUTION (monotonic stack variant):** 828, 2262, 1856, 2681 — four problems all using the "nearest smaller/larger element" window. Derive each from scratch before looking at code.
- **TRICK (work backwards):** 880, 1354 — both require realising that forward simulation is intractable, backwards with mod is O(log n)
- **MOD_ARITH (prefix sum mod P):** 1590, 2845 — both reduce to "find two indices with same residue" — this pattern recurs endlessly at 1900+

**Priority 2 — combinatorics cluster:**
- **PERM_COMB (grid paths):** 1643 — C(H+V-1, H) for greedy path decisions. Derive the formula before memorising it.
- **BITMASK DP:** 2741, 1799 — two different styles; 2741 is permutation ordering, 1799 is pairing with GCD scoring

**Priority 3 — identity tricks:**
- **2354 (popcount identity):** popcount(a AND b) + popcount(a OR b) = popcount(a) + popcount(b) — worth knowing cold
- **1686 (Stone Game VI greedy):** sort by combined value a[i]+b[i] — understand the proof, not just the trick
- **1131 (Manhattan distance sign expansion)** — generalises to any problem with absolute value sums

**Skip for 1700 target:** TRIPLE_COUNT (only 1 problem, high implementation cost), STREAK (specific to arithmetic sequence problems).

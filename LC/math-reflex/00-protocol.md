# Math Reflex Protocol

How atomic-fact math reflex gets installed, maintained, and graduated. Companion to `math-reflex-syllabus.md` (the concept-level roadmap). This file is the drill-level execution layer.

## Why this exists

The pain point is concrete: deriving `n(n-1)/2` from scratch took ~20 minutes. Counting integers in `[a, b]` took 3-5 minutes. These are atomic facts — they should be **5-second recall**, not minutes-long derivations. In a 90-min contest with 4 problems, leaking 25 min on facts that should cost zero is the difference between landing Q2 and not.

This protocol installs those facts to genuine reflex.

## The two states a fact can be in

| State | Definition |
|-------|------------|
| **Installing** | Currently being drilled. Answer not yet reflex. |
| **Maintaining** | Graduated — kept warm via spaced rep so it doesn't decay. |

A fact moves from installing to maintaining only when it passes the graduation bar.

## Graduation bar

A micro-fact is **graduated** when all three hold:

1. Answered in **<5 seconds**, cold, no warm-up
2. Asked in **mixed order** with other facts (no clustering — clustering tests pattern-match, not reflex)
3. Holds across **3 consecutive days** of mixed quiz

If a fact is *known* but takes 15 seconds, it is not graduated. Known ≠ reflex. Under contest pressure, "known" becomes "20-min derivation."

A whole **band** is graduated when 100% of its micro-facts are graduated. Then the next band opens for install.

## Progression model

Bands install one at a time, in syllabus order. Prior bands stay active as maintenance.

```
Start    →  Install Band 1400
Then     →  Install Band 1500   |  Maintain 1400
Then     →  Install Band 1600   |  Maintain 1400 + 1500
Then     →  Install Band 1700   |  Maintain 1400 + 1500 + 1600
Then     →  Install Band 1800   |  Maintain 1400 → 1700
... and so on up the syllabus toward Guardian
```

**No timing on bands.** Some install fast (mostly half-known facts), others take longer (genuinely unfamiliar machinery). Graduation is by bar passed, not calendar. Same protocol as zerotrac: don't rush bumps.

## Daily session structure

Total: ~10 min/day. Per-session split:

| Slot | Time | Content |
|------|------|---------|
| **Install** | ~7 min | The new band currently being drilled. Cold recall on unfamiliar facts. |
| **Maintenance** | ~3 min | Mixed quiz across all prior graduated bands. Spaced rep to prevent decay. |

The 70/30 ratio is per-session, not per-month. Every daily session is internally split this way regardless of which band is being installed.

## Why maintenance is non-optional

Without maintenance, by the time you're installing Band 1700, the Band 1400 anchors decay. The 20-min `n(n-1)/2` derivation comes back. Spaced rep is what makes the install permanent. Prior bands stay in the rotation forever — they never "graduate out" of maintenance, just out of install.

## How a fact gets quizzed

Mixed order means: shuffle the deck. Not "all pair-counting facts in a row, then all mod facts." That's pattern-matching the slot, not retrieving the fact cold. The quiz should pull facts at random from the install band + maintenance pool, no warning what's next.

Application-level over formula-level. "Given n=20, pairs?" → 190 is a real reflex test. "What's the pair count formula?" → `n(n-1)/2` only tests memorization, not application speed.

## Two-layer architecture

The system has two complementary file layers. Keep them separate — they serve different jobs.

### Layer 1 — Syllabus (topic-organized, vertical slice)

`topics/0N-topic.md` — one file per math topic (Parity, Arithmetic Sums, Permutations & Combinations, etc.), built in difficulty order (easiest topic first).

Each topic file has the shape:

```
# Topic Name [first-appearance rating]

Empirical frequency table (count of topic-tagged problems per band).

## a. Subtopic name [required-from rating]
Depends on: <other topic → subtopic> [rating]   (optional)
Cards (N):
  - a.1 — card title
  - a.2 — card title
  ...

## b. Next subtopic [required-from rating]
...
```

The rating bracket on a **topic** = where it first appears in problems. The rating bracket on a **subtopic** = the lowest target rating at which this subtopic is mandatory. If your target rating is below the subtopic bracket, skip it.

**Card titles only. No answers / formulas / examples in topic files.** Card content gets unpacked via Socratic drill when the card is installed.

### Layer 2 — Drill (band-organized, horizontal slice)

`drill/0N-band-XXXX.md` — one file per zerotrac rating band. Generated by filtering the topic syllabus: pull every card whose subtopic rating ≤ this band's upper edge. This is the daily-quiz unit.

Each drill file lists cards in mixed order (not grouped by topic — clustering kills the reflex test) and tracks status per card.

### Why both layers

| View | Use case |
|------|----------|
| **Topic file** (vertical) | "I want to understand Parity across all ratings — show me the arc from a.1 through j.1." Reading / studying. |
| **Drill file** (horizontal) | "Today I install Band 1400 — give me every card mandatory at 1400 in mixed order." Daily reps. |

The drill file is a *projection* of the topic syllabus through the band rating gate. It's not a separate authority — the topic file is the source of truth.

## Where things live

| Path | Purpose |
|------|---------|
| `00-protocol.md` | This file. The rules. |
| `topics/0N-topic.md` | Topic syllabus (Layer 1). Subtopics + cards, rating-bracketed. No card content. |
| `drill/0N-band-XXXX.md` | Per-band drill projection (Layer 2). Generated from topics, mixed order, with status markers. |
| `log.md` | Daily drill log. Date, band installed, prior bands maintained, misses, notes. |

The legacy `LC/math-reflex-syllabus.md` is **obsolete** — it was a pre-empirical guess. The empirical analyses in `LC/math-band-XXXX-XXXX.md` are the data source the topic files are built from.

## Status markers used in band files

For each micro-fact:

| Marker | Meaning |
|--------|---------|
| `◯` | Not yet drilled |
| `◐` | Currently installing — answer known but not yet <5sec across 3 days |
| `●` | Graduated — moved to maintenance pool |

## What "maximizing math reflex" actually means here

Not the full math-reflex-syllabus marched through end-to-end (that's maximizing the syllabus). Not abstract math practice. The maximize target is **atomic-fact reflex on a tight micro-fact set, drilled to genuine <5-second answer, band by band, with prior bands kept warm**. That's the system this protocol implements.

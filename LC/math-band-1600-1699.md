# Section 1 — Geometry (top topic, 18% of math problems)

## 1.1 Lattice points inside / on circles

**Fact:** Lattice points inside circle `(x₀, y₀, r)`: for each integer `x` in `[x₀-r, x₀+r]`, the valid `y` range is `[y₀ - √(r²-(x-x₀)²), y₀ + √(r²-(x-x₀)²)]`. Sum the integer counts.

**LC problems:**
- *Count Lattice Points Inside a Circle* (LC 2249, 1602)

## 1.2 Largest square inside intersection of rectangles

**LC problems:**
- *Find Largest Area of Square Inside Two Rectangles* (LC 3047, 1601) — for each pair, intersection rectangle area; square side = `min(w, h)` of intersection

## 1.3 Distance reachability with budget

**LC problems:**
- *Escape The Ghosts* (LC 789, 1611) — if ghost's manhattan distance to target ≤ player's, ghost can intercept

## 1.4 Coordinate signal / quality

**LC problems:**
- *Coordinate With Maximum Network Quality* (LC 1620, 1665) — Euclidean distance with quality decay; brute force coordinates in bounding box

## 1.5 Distance on grid (Manhattan)

**LC problems:**
- *As Far from Land as Possible* (LC 1162, 1666) — multi-source BFS from all lands
- *Multi Source Flood Fill* (LC 3905, 1671) — same pattern

## 1.6 Polygon / corner counting

**LC problems:**
- *Number Of Corner Rectangles* (LC 750, 1651) — for each pair of rows, count common columns; choose 2 from common
- *Count Collisions of Monkeys on a Polygon* (LC 2550, 1662) — `2^n - 2` ways; permutation/MOD heavy
- *Minimum Lines to Represent a Line Chart* (LC 2280, 1680) — count slope changes; slope as `dx/dy` reduced by GCD

## 1.7 Grid path / staircase / spiral

**LC problems:**
- *Spiral Matrix III* (LC 885, 1678)
- *Minimum Operations to Write the Letter Y on a Grid* (LC 3071, 1689)
- *Maximize Area of Square Hole in Grid* (LC 2943, 1677) — find longest consecutive run of removable bars

## 1.8 Points inside a square / axis-aligned constraint

**LC problems:**
- *Maximum Points Inside the Square* (LC 3143, 1696) — `max(|x|, |y|)` is Chebyshev; sort by Chebyshev, accept until tag conflict

# Section 2 — Bit operations (15% of math problems)

## 2.1 XOR coordinate / prefix XOR on grid

**LC problems:**
- *Find Kth Largest XOR Coordinate Value* (LC 1738, 1671) — `grid_xor[i][j] = grid_xor[i-1][j] ^ grid_xor[i][j-1] ^ grid_xor[i-1][j-1] ^ grid[i][j]` (2D prefix XOR via inclusion-exclusion-like XOR)

## 2.2 Concatenating binary representations

**LC problems:**
- *Concatenation of Consecutive Binary Numbers* (LC 1680, 1629) — `result = (result << bitLen(i)) + i mod (10⁹+7)`. Need modular multiplication.

## 2.3 Power of 2 representation

**Fact:** Any positive integer can be written as `Σ ± 2^bi` — minimum number of terms = `popcount(n XOR (3n))` (popcount of the "borrow/carry pattern"). Greedy left-to-right also works.

**LC problems:**
- *Minimum Operations to Reduce an Integer to 0* (LC 2571, 1649) — count "transitions" in binary representation + 1

## 2.4 AND / OR analysis

**LC problems:**
- *Largest Combination With Bitwise AND Greater Than Zero* (LC 2275, 1642) — for each bit i, count nums with bit i set; max wins
- *Maximum XOR After Operations* (LC 2317, 1678) — `OR of all = max XOR achievable` (because operation lets you turn off individual bits per number)
- *Apply Bitwise Operations to Make Strings Equal* (LC 2546, 1604) — both have at least one '1' iff convertible (op preserves whether any '1' exists)

## 2.5 Range product of powers

**LC problems:**
- *Range Product Queries of Powers* (LC 2438, 1609) — extract powers (bit positions), precompute prefix products mod 10⁹+7

## 2.6 Encoded base operations

**LC problems:**
- *Convert to Base -2* (LC 1017, 1697) — handle negative base division/remainder
- *Min Operations to Make Binary Palindrome* (LC 3766, 1656) — for each n, find nearest palindrome in bit space

## 2.7 Doubling / increment operations

**LC problems:**
- *Min Function Calls to Make Target Array* (LC 1558, 1637) — for each bit set in nums[i], that's a "double". Plus 1 per nums[i] for the final increment.

# Section 4 — Pair counting (12% of math problems)

## 4.1 Caesar-cipher / equivalence-class pair counting

**LC problems:**
- *Count Caesar Cipher Pairs* (LC 3805, 1624) — normalize each word, group, sum `C(count, 2)`. Same pattern as 1400 Caesar but at harder rating.
- *Count Almost Equal Pairs I* (LC 3265, 1661) — for each num, generate all swap variants; hash equivalence class

## 4.2 Pair count via target invariant

**LC problems:**
- *Count Number of Bad Pairs* (LC 2364, 1622) — `j - i != nums[j] - nums[i]` ⇔ `nums[j] - j != nums[i] - i` → count pairs with same `nums[i] - i`
- *Sum of Digit Differences of All Pairs* (LC 3153, 1645) — contribution by digit position: for each position, count distinct digits, contribute `n² - Σ count²` / 2

## 4.3 Pair count via "doubled" relation

**LC problems:**
- *Min Absolute Distance Between Mirror Pairs* (LC 3761, 1668) — for each num, compute reverse, store first/last seen index, pair with same reverse

## 4.4 Pair count via age / threshold

**LC problems:**
- *Friends Of Appropriate Ages* (LC 825, 1697) — count ages, for each (a,b) pair satisfying constraints, sum `count[a] * count[b]`

## 4.5 Pair count with structural insight

**LC problems:**
- *Count Unreachable Pairs of Nodes in Undirected Graph* (LC 2316, 1604) — connected components; pair count = `Σ size[i] × (n - cum_size)`

## 4.6 Two-array pair sums

**LC problems:**
- *Finding Pairs With a Certain Sum* (LC 1865, 1680) — hashmap of nums2 frequencies; for each query iterate nums1

# Section 13 — Arithmetic progression / consecutive sum (5%)

## 13.1 Consecutive numbers sum

**Fact:** n = sum of k consecutive positives starting from a: `n = k*a + k(k-1)/2` → `a = (n/k - (k-1)/2)`. Valid iff `a ≥ 1` and integer.

**LC problems:**
- *Consecutive Numbers Sum* (LC 829, 1694) — try k from 1 to about √(2n); count valid; also divisor-based interpretation
- *Append K Integers With Minimal Sum* (LC 2195, 1658) — sum 1..maxNeeded; subtract conflicts
- *Construct Longest New String* (LC 2745, 1607) — see 9.2

| BIT_OPS | 14% | 7% | 13% | **15%** |

**The "math fraction" slowly declines as bands rise** — at higher ratings, more problems are algorithmic synthesis (data structures, graph, DP combinations) rather than pure math reasoning. But the math problems get HARDER per-problem — the geometry at 1600 is real geometry, the bit ops require multi-pattern combination, the mod arithmetic involves modular inverse / exponentiation.

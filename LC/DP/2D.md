

> [!info] 2D DP is identical to 1D DP — the only difference is that the state needs two variables instead of one to uniquely identify a subproblem.

If 1D DP is new to you, read `1D-DP.md` first. Everything here builds directly on that foundation — same four-step framework, same derivation process, just applied to a grid instead of a sequence.

---

## The problem — unique paths in a grid

You have an `m × n` grid. You start at the top-left corner `(0, 0)` and want to reach the bottom-right corner `(m-1, n-1)`. You can only move **right** or **down**. How many unique paths exist?

---

## Step 1 — define the state

Before writing any recurrence, define what the function means in plain English.

A subproblem here is: "how many unique paths are there to reach cell `(i, j)`?" That answer depends on exactly two things — the row `i` and the column `j`. Knowing just `i` is not enough, knowing just `j` is not enough. You need both to uniquely identify the subproblem.

```
State: f(i, j) = number of unique paths to reach cell (i, j)
```

Two variables in the state → **2D DP**. The table will be a 2D array.

---

## Step 2 — write the recurrence

Cell `(i, j)` can only be reached from the cell above `(i-1, j)` or the cell to the left `(i, j-1)` — because movement is only right or down. So the total number of paths to `(i, j)` is the sum of paths to those two cells:

```
f(i, j) = f(i-1, j) + f(i, j-1)
```

---

## Step 3 — identify base cases

The entire first row `(0, j)` can only be reached by moving right from `(0, 0)` — there is no row above it. Every cell in the first row has exactly **1 path**.

The entire first column `(i, 0)` can only be reached by moving down from `(0, 0)` — there is no column to its left. Every cell in the first column has exactly **1 path**.

```
f(0, j) = 1   for all j   (first row)
f(i, 0) = 1   for all i   (first column)
```

---

## The brute-force recursion

Translating the recurrence and base cases directly into code:

```java
int f(int i, int j) {
    if (i == 0 || j == 0) return 1;
    return f(i-1, j) + f(i, j-1);
}
// call: f(m-1, n-1)
```

Time complexity using the rule from 1D DP (`Time = branching_factor ^ depth`):

- Branching factor = 2 (each call spawns two recursive calls)
- Depth = `(m-1) + (n-1) = m+n-2` (each call reduces i by 1 or j by 1, bottoming out at row 0 or column 0)

```
Time = 2^(m+n-2) = O(2^(m+n))   ← exponential, broken at scale
```

---

## Step 4 — fill the table bottom-up

There are `m × n` unique subproblems — one per cell. With memoization, each is computed exactly once, dropping time to **O(m×n)**. Bottom-up fills the same table iteratively:

```java
int uniquePaths(int m, int n) {
    int[][] dp = new int[m][n];

    for (int i = 0; i < m; i++) dp[i][0] = 1;  // first column
    for (int j = 0; j < n; j++) dp[0][j] = 1;  // first row

    for (int i = 1; i < m; i++)
        for (int j = 1; j < n; j++)
            dp[i][j] = dp[i-1][j] + dp[i][j-1];

    return dp[m-1][n-1];
}
```

Time: **O(m×n)**. Space: **O(m×n)**.

---

## Space optimisation — from O(m×n) to O(n)

Look at the recurrence: `dp[i][j] = dp[i-1][j] + dp[i][j-1]`. At any row `i`, only row `i-1` (the previous row) and the current row are ever needed. Every row above that is never touched again.

So the full grid collapses to a single array — reused row by row:

```java
int uniquePaths(int m, int n) {
    int[] dp = new int[n];
    Arrays.fill(dp, 1);          // first row is all 1s

    for (int i = 1; i < m; i++)
        for (int j = 1; j < n; j++)
            dp[j] = dp[j] + dp[j-1];
            // dp[j] before update  = value from row above (prev row)
            // dp[j-1]              = already updated left cell (curr row)

    return dp[n-1];
}
```

Space drops from **O(m×n) → O(n)**.

> [!important] Why not `O(1)` like Fibonacci? In Fibonacci, only 2 previous values were needed — they collapsed to 2 variables. Here, the entire previous row of n values is needed at every step. O(n) is the floor.

---

## The reference vs copy trap

A common bug when writing two-row space optimisation in Java:

```java
prev = curr;        // WRONG — both variables now point to the same array
prev = curr.clone(); // RIGHT — creates a new independent copy
```

In Java, arrays are objects. `prev = curr` does not copy the array — it makes both variables point to the same memory. Writing to `curr` in the next iteration then corrupts `prev`. Using a single array (as shown above) sidesteps this entirely.

---

## The 2D DP pattern

```
1. State      — f(i,j) = what does this cell mean in plain English?
2. Recurrence — f(i,j) = combination of neighbouring states
3. Base cases — edges, corners, or trivially known cells
4. Fill order — row by row, left to right (so every cell's dependencies are ready)
```

> [!tip] In contests: read the constraint on m and n. If m×n ≤ 10^6, a full 2D table fits in memory. If m×n > 10^6, look for a space optimisation — usually the single-row rolling array shown above.

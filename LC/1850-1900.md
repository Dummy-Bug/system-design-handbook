### #1 — Minimum Generations to Target Point

| Field | Value |
|-------|-------|
| Date | 2026-05-19 |
| Link | https://leetcode.com/problems/minimum-generations-to-target-point |
| Rating | 1883 |
| AC | Y |
| Time | 45min end-to-end (thinking → code → AC, no hints) |
| Pattern | BFS-style generation expansion with newcomer-only pair pruning |
| Revision due | 2026-06-02 |

---

#### Approach

Generation 0 is the initial point list. Each subsequent generation k is formed by computing floored midpoints of every pair from points across generations 0..k-1. Return smallest k such that target appears in some generation, or -1 if it never appears.

Constraint analysis dictates strategy:
- `points.length ≤ 20`, coords `0..6` → at most `7^3 = 343` distinct points ever exist
- The state space is tiny — brute force generation expansion is the intended solution

**Newcomer-only pair pruning:** Naive approach recomputes every pair every generation — O(N²) per generation with N growing. Key observation: if both points existed before generation k-1, their midpoint was already computed in an earlier generation. So in generation k, only pairs where *at least one point is new* (from generation k-1) can produce genuinely new midpoints.

Implementation: maintain a `start` pointer indicating where the previous generation's new points begin in the list. For the new pass, iterate `j` from `start` to `n-1` (new points only as the "j" side), and `i` from `0` to `n-1` with constraint `j > i`. This guarantees at least one of the pair is from the most recent generation. First iteration uses `start=0` to cover all initial pairs.

Dedup via `HashSet<String>` on `"x,y,z"` keys — coords are tiny so string concat is fine. `set.add(...)` returning true means "new point, add to list and set flag."

Termination: if a generation adds no new points (`flag` stays false), no further progress is possible → return -1.

**Off-by-one trap (got bit by it):** First attempt returned `k` on match, but the loop body produces generation `k+1` (since k=0 enters loop with generation 0 = initial). Fixed by returning `k+1` on match. Also added an upfront check: if target is in the initial points, return 0 immediately (otherwise the code never gets a chance to recognize generation 0).

---

#### Lessons

- **Constraint reading drove the approach.** N≤20 + coords 0..6 makes the state space tiny — there's no reason to look for anything clever. Brute force *is* the intended solution. Saved time by not hunting for a non-existent optimization.
- **Newcomer-only pruning is a reusable pattern** — anytime generations build on previous ones (BFS layer expansion, transitive closure, etc.), only pairs involving the latest layer produce new results.
- **Off-by-one on generation count** — when a loop body produces "the next thing" and you have a counter starting at 0, decide upfront whether the counter reflects "iterations done" or "current generation being built." Trace one example before coding.

### #2 — Even Sum Subgraphs

| Field | Value |
|-------|-------|
| Date | 2026-05-19 |
| Link | (LC — Even Sum Subgraphs, n ≤ 13) |
| Rating | 1859 |
| AC | Y |
| Time | 46min (clean derivation, multiple compile/logic bugs in iteration) |
| Pattern | Subset enumeration + connectivity check (induced subgraph) |
| Revision due | 2026-06-02 |

---

#### Problem

Undirected graph with `n` nodes (`n ≤ 13`), `nums[i] ∈ {0,1}`. Count non-empty subsets `s` such that the induced subgraph on `s` is connected AND the sum of `nums[i]` over `s` is even.

---

#### Approach (the derivation)

Constraint reading came first: `n ≤ 13` → `2^n = 8192` subsets max. Brute force subset enumeration is well within budget.

The shape of the algorithm:
1. Generate all non-empty subsets of `{0..n-1}`.
2. Filter to subsets whose `nums` sum is even.
3. For each remaining subset, check whether the induced subgraph is connected via BFS/DFS.

Complexity: `2^n` subsets × `O(n²)` connectivity check ≈ `2^13 × 13² ≈ 1.4M` ops. Trivial.

---

#### Implementation pitfalls (real ones hit during coding)

1. **Reference vs copy when storing subsets** — `this.subsets.add(stack)` stores a *reference* to the same mutable Deque. Fix: `new ArrayDeque<>(stack)`.
2. **Pushing values instead of indices** — `stack.push(nums[index])` pushed `0` or `1`, not the node index. Fix: `stack.push(index)`.
3. **Off-by-one in method signature** — 3 args passed, signature took 4. Java caught it.
4. **`adjMatrix[node]` is `int[]`, not `int[][]`** — tried `for (int[] neighbors : adjMatrix[node])`. Fix: iterate over `neighbor` index directly.
5. **Starting node not added to visited** — `visited.size()` was off by one. Fix: `visited.add(start)` before the BFS loop.

---

#### Alternative: Bitmask (taught after AC — first exposure)

`n ≤ 13` is a classic bitmask signal — small `n`, "iterate all subsets," and each subset's state fits in an `int`. Every subset of `{0..n-1}` maps 1-to-1 with an integer in `[0, 2^n - 1]`: bit `i` of the integer tells you whether element `i` is in the subset.

**Core idioms (memorise):**

| Operation | Code | Note |
|---|---|---|
| Test bit `i` | `(mask >> i) & 1` or `(mask & (1 << i)) != 0` | Membership |
| Set bit `i` | `mask \| (1 << i)` | Add to set |
| Clear bit `i` | `mask & ~(1 << i)` | Remove from set |
| Toggle bit `i` | `mask ^ (1 << i)` | Flip |
| Clear lowest 1 | `mask & (mask - 1)` | Drop one element |
| Isolate lowest 1 | `mask & -mask` | Get just the lowest bit |
| Lowest 1 position | `Integer.numberOfTrailingZeros(mask)` | Index of lowest set bit |
| Popcount | `Integer.bitCount(mask)` | Number of elements in set |
| Empty subset | `0` | |
| Full subset | `(1 << n) - 1` | All `n` lowest bits set |

**Iterating set bits — the standard idiom:**

```java
while (frontier != 0) {
    int next = Integer.numberOfTrailingZeros(frontier);
    // process `next`
    frontier &= frontier - 1;
}
```

**The connectivity speedup line:**

```java
int frontier = adj[node] & mask & ~visited;
```

In one expression: take node's neighbors, keep only those in the current subset, drop the visited ones.

---

#### Lessons

- **Constraint-first reading.** `n ≤ 13` instantly screamed "subset enumeration." Brute force math confirmed feasibility before writing a single line.
- **Bitmask is a representation, not an algorithm.** It's just a way of encoding a set as an integer so that set ops become bit ops.
- **Bitmask signal:** `n ≤ 20-22` + "iterate all subsets" or "state = which elements are picked."
- **Implementation discipline:** reference-vs-copy, indices-vs-values, dimension mismatch — all caught only by tracing examples. The 5-step ritual would have caught most of these.

### #3 — Minimum Operations to Sort String

| Field | Value |
|-------|-------|
| Date | 2026-05-19 |
| Link | — |
| Rating | 1860 |
| AC | N (hinted) |
| Time | hinted |
| Pattern | Greedy / String — unsorted window + first/last occurrence of min/max |
| Revision due | 2026-06-02 |

---

#### Problem

Given a string `s`, each operation lets you sort any non-entire substring (non-descending). Return the minimum operations to sort `s`, or `-1` if impossible.

---

#### User's approach and the bug

User correctly identified the answer is always 0 / 1 / 2 / 3 / -1 and built a case analysis around global min/max positions. The logic was:

- 0 → already sorted
- n=2 and not sorted → -1
- min at position 0 OR max at position n-1 → 1 op
- max at position 0 AND min at position n-1 → 3 ops
- else → 2 ops

**Bug:** The 3-op condition fired on `"bba"` (max=`'b'` at pos 0, min=`'a'` at pos 2), returning 3. Correct answer is 2 — `'b'` appears at both positions 0 and 1, so you can push it to the end without touching position 0.

---

#### The correct conditions

**1 op** is possible iff the unsorted window — first-to-last position that differs from the globally sorted string — is NOT the full string.

**3 ops** are needed iff:
- The unsorted window IS the full string `[0, n-1]`
- AND `maxChar` appears ONLY at position 0 (no copy in `[1..n-1]`)
- AND `minChar` appears ONLY at position `n-1` (no copy in `[0..n-2]`)

---

---

#### Lessons

- **Duplicate characters break "position of global min/max" logic.** Always ask: "does this character appear anywhere else?"
- **The correct 3-op condition is about uniqueness, not presence.** `lastIndexOf(maxChar) == 0` means max exists ONLY at 0.
- **Unsorted window = compare s to sorted(s), find first/last mismatch.** Cleaner and more general than hand-rolled position checks.
- **AC with hint — need cold re-solve.** Schedule a clean attempt without looking at the solution.

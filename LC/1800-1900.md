### #1 — Minimum Generations to Target Point

| Field | Value |
|-------|-------|
| Date | 2026-05-19 |
| Link | https://leetcode.com/problems/minimum-generations-to-target-point |
| Rating | 1883 |
| AC | Y |
| Time | 45min end-to-end (thinking → code → AC, no hints) |
| Pattern | BFS-style generation expansion with newcomer-only pair pruning |
| Revision due | 2026-06-02 |

---

#### Approach

Generation 0 is the initial point list. Each subsequent generation k is formed by computing floored midpoints of every pair from points across generations 0..k-1. Return smallest k such that target appears in some generation, or -1 if it never appears.

Constraint analysis dictates strategy:
- `points.length ≤ 20`, coords `0..6` → at most `7^3 = 343` distinct points ever exist
- The state space is tiny — brute force generation expansion is the intended solution

**Newcomer-only pair pruning:** Naive approach recomputes every pair every generation — O(N²) per generation with N growing. Key observation: if both points existed before generation k-1, their midpoint was already computed in an earlier generation. So in generation k, only pairs where *at least one point is new* (from generation k-1) can produce genuinely new midpoints.

Implementation: maintain a `start` pointer indicating where the previous generation's new points begin in the list. For the new pass, iterate `j` from `start` to `n-1` (new points only as the "j" side), and `i` from `0` to `n-1` with constraint `j > i`. This guarantees at least one of the pair is from the most recent generation. First iteration uses `start=0` to cover all initial pairs.

Dedup via `HashSet<String>` on `"x,y,z"` keys — coords are tiny so string concat is fine. `set.add(...)` returning true means "new point, add to list and set flag."

Termination: if a generation adds no new points (`flag` stays false), no further progress is possible → return -1.

**Off-by-one trap (got bit by it):** First attempt returned `k` on match, but the loop body produces generation `k+1` (since k=0 enters loop with generation 0 = initial). Fixed by returning `k+1` on match. Also added an upfront check: if target is in the initial points, return 0 immediately (otherwise the code never gets a chance to recognize generation 0).

---

#### Final solution

```java
class Solution {
    public int minGenerations(int[][] points, int[] target) {
        List<int[]> al = new ArrayList<>();
        Set<String> set = new HashSet<>();

        for (int[] point : points) {
            if (point[0] == target[0] && point[1] == target[1] && point[2] == target[2]) {
                return 0;
            }
            al.add(point);
            set.add(point[0] + "," + point[1] + "," + point[2]);
        }

        boolean flag = true;
        int start = 0;
        int k = 0;

        while (flag) {
            flag = false;
            int n = al.size();
            int i;
            for (i = 0; i < n; i++) {
                for (int j = start; j < n; j++) {
                    if (j <= i) continue;
                    int px = (al.get(i)[0] + al.get(j)[0]) / 2;
                    int py = (al.get(i)[1] + al.get(j)[1]) / 2;
                    int pz = (al.get(i)[2] + al.get(j)[2]) / 2;

                    if (px == target[0] && py == target[1] && pz == target[2]) {
                        return k + 1;
                    }
                    if (set.add(px + "," + py + "," + pz)) {
                        flag = true;
                        al.add(new int[] { px, py, pz });
                    }
                }
            }
            start = i;
            k++;
        }
        return -1;
    }
}
```

---

#### Lessons

- **Constraint reading drove the approach.** N≤20 + coords 0..6 makes the state space tiny — there's no reason to look for anything clever. Brute force *is* the intended solution. Saved time by not hunting for a non-existent optimization.
- **Newcomer-only pruning is a reusable pattern** — anytime generations build on previous ones (BFS layer expansion, transitive closure, etc.), only pairs involving the latest layer produce new results.
- **Off-by-one on generation count** — when a loop body produces "the next thing" and you have a counter starting at 0, decide upfront whether the counter reflects "iterations done" or "current generation being built." Trace one example before coding.
- **First problem in 1800-1900 band, AC at 45min** — derivation clause didn't fire (under cap anyway). Good signal that the band jump from 1700-1750 is reasonable.

### #2 — Even Sum Subgraphs

| Field | Value |
|-------|-------|
| Date | 2026-05-19 |
| Link | (LC — Even Sum Subgraphs, n ≤ 13) |
| Rating | 1859 |
| AC | Y |
| Time | 46min (clean derivation, multiple compile/logic bugs in iteration) |
| Pattern | Subset enumeration + connectivity check (induced subgraph) |
| Revision due | 2026-06-02 |

---

#### Problem

Undirected graph with `n` nodes (`n ≤ 13`), `nums[i] ∈ {0,1}`. Count non-empty subsets `s` such that the induced subgraph on `s` is connected AND the sum of `nums[i]` over `s` is even.

---

#### Approach (the derivation)

Constraint reading came first: `n ≤ 13` → `2^n = 8192` subsets max. Coords on the graph are tiny. Brute force subset enumeration is well within budget.

The shape of the algorithm:
1. Generate all non-empty subsets of `{0..n-1}`.
2. Filter to subsets whose `nums` sum is even.
3. For each remaining subset, check whether the induced subgraph is connected via BFS/DFS.

Complexity: `2^n` subsets × `O(n²)` connectivity check (BFS over at most `n` nodes with up to `n²` edges) ≈ `2^13 × 13² ≈ 1.4M` ops. Trivial.

This was derived in under 10 minutes — clean dissection, no wrong paths. The complexity math was done upfront, which is the right habit: confirm the brute force fits before designing anything cleverer.

---

#### Implementation pitfalls (real ones hit during coding)

The algorithm was right. The bugs were all in execution. Logged for memory:

1. **Reference vs copy when storing subsets** — `this.subsets.add(stack)` stores a *reference* to the same mutable Deque. After backtracking, every entry points to the same (eventually empty) stack. Fix: `new ArrayDeque<>(stack)`.

2. **Pushing values instead of indices** — `stack.push(nums[index])` pushed `0` or `1` (the value), not the node index. Then BFS started from a "value" rather than a node. Fix: `stack.push(index)`.

3. **Off-by-one in method signature** — `findAllSubsets(nums, 0, 0)` had 3 args, signature took 4. Java caught it.

4. **`adjMatrix[node]` is `int[]`, not `int[][]`** — tried to do `for (int[] neighbors : adjMatrix[node])`. Wrong dimension. Fix: `for (int neighbor = 0; neighbor < n; neighbor++)`.

5. **Starting node not added to visited** — `q.offer(subset.peek())` enqueued the start, but never added it to `visited`. `visited.size()` was off by one. Fix: `visited.add(start)` before the BFS loop.

---

#### Generic solution (no bitmask) — the version that AC'd

```java
class Solution {
    private List<Deque<Integer>> subsets = new ArrayList<>();
    private int[][] adjMatrix;

    public int evenSumSubgraphs(int[] nums, int[][] edges) {
        int n = nums.length;
        this.adjMatrix = new int[n][n];
        findAllSubsets(nums, 0, 0, new ArrayDeque<>());
        createGraph(edges);

        int count = 0;
        for (Deque<Integer> subset : this.subsets) {
            if (isConnected(subset, n)) count++;
        }
        return count;
    }

    private void createGraph(int[][] edges) {
        for (int[] edge : edges) {
            adjMatrix[edge[0]][edge[1]] = 1;
            adjMatrix[edge[1]][edge[0]] = 1;
        }
    }

    private void findAllSubsets(int[] nums, int index, int sum, Deque<Integer> stack) {
        if (index == nums.length) {
            if ((sum & 1) == 0 && !stack.isEmpty()) {
                subsets.add(new ArrayDeque<>(stack));
            }
            return;
        }
        stack.push(index);
        findAllSubsets(nums, index + 1, sum + nums[index], stack);
        stack.pop();
        findAllSubsets(nums, index + 1, sum, stack);
    }

    private boolean isConnected(Deque<Integer> subset, int n) {
        Set<Integer> inSubset = new HashSet<>(subset);
        Set<Integer> visited = new HashSet<>();
        Deque<Integer> q = new ArrayDeque<>();
        int start = subset.peek();
        q.offer(start);
        visited.add(start);
        while (!q.isEmpty()) {
            int node = q.poll();
            for (int neighbor = 0; neighbor < n; neighbor++) {
                if (adjMatrix[node][neighbor] == 1
                        && inSubset.contains(neighbor)
                        && !visited.contains(neighbor)) {
                    visited.add(neighbor);
                    q.offer(neighbor);
                }
            }
        }
        return visited.size() == inSubset.size();
    }
}
```

Cleaner version inlines connectivity check during recursion (no `subsets` list), dropping memory from `O(2^n × n)` to `O(n)`.

---

#### Alternative: Bitmask (taught after AC — first exposure)

`n ≤ 13` is a classic bitmask signal — small `n`, "iterate all subsets," and each subset's state fits in an `int`. Every subset of `{0..n-1}` maps 1-to-1 with an integer in `[0, 2^n - 1]`: bit `i` of the integer tells you whether element `i` is in the subset.

**The mental model shift:** stop thinking "the integer 13" and start thinking "bits 0, 2, 3 are on." We're using the int as a bit vector — `n` boolean flags packed into one number. Decimal value is incidental.

**Core idioms (memorise):**

| Operation | Code | Note |
|---|---|---|
| Test bit `i` | `(mask >> i) & 1` or `(mask & (1 << i)) != 0` | Membership |
| Set bit `i` | `mask \| (1 << i)` | Add to set |
| Clear bit `i` | `mask & ~(1 << i)` | Remove from set |
| Toggle bit `i` | `mask ^ (1 << i)` | Flip |
| Clear lowest 1 | `mask & (mask - 1)` | Drop one element |
| Isolate lowest 1 | `mask & -mask` | Get just the lowest bit |
| Lowest 1 position | `Integer.numberOfTrailingZeros(mask)` | Index of lowest set bit |
| Popcount | `Integer.bitCount(mask)` | Number of elements in set |
| Empty subset | `0` | |
| Full subset | `(1 << n) - 1` | All `n` lowest bits set |

**Why bitmask wins:**
1. **Subset IS the state** — a 4-byte `int`, no allocation, no `ArrayDeque` copying. Drops memory from `O(2^n × n)` to `O(2^n × 4 bytes)` if you store them, or `O(1)` if you stream.
2. **Set operations collapse to one CPU op** — `set.contains(i)` (HashSet ~10s of ns) becomes `(mask >> i) & 1` (sub-ns). Union/intersection/difference become `|`, `&`, `& ~`.
3. **Subsets become array indices** — `dp[mask]` is direct array access, no HashMap hashing. This is the gateway to bitmask DP (TSP, set cover, "minimum cost to visit all states").

**Iterating set bits — the standard idiom:**

```java
while (frontier != 0) {
    int next = Integer.numberOfTrailingZeros(frontier);
    // process `next`
    frontier &= frontier - 1;
}
```

`numberOfTrailingZeros` finds the lowest set bit's position; `&= x - 1` clears it. Loop runs exactly `popcount(frontier)` times — no wasted iterations over zero bits like `for (i = 0; i < n; i++)` would do.

**Why `x & (x - 1)` clears the lowest set bit:** subtracting `1` flips the lowest `1` to `0` and every bit *below* it from `0` to `1`. AND-ing with the original wipes the lowest `1` and everything below, preserving everything above.

```
frontier:       0110   (6)
frontier - 1:   0101   (5)
AND:            0100   (4)   ← lowest 1 (bit 1) cleared, bit 2 preserved
```

**The connectivity speedup line — the heart of the bitmask version:**

```java
int frontier = adj[node] & mask & ~visited;
```

In one expression: take node's neighbors, keep only those in the current subset, drop the visited ones. This replaces a `for (int v = 0; v < n; v++)` loop with two HashSet lookups inside — collapsed to three integer ANDs.

**Full bitmask solution:**

```java
class Solution {
    public int evenSumSubgraphs(int[] nums, int[][] edges) {
        int n = nums.length;

        int[] adj = new int[n];
        for (int[] e : edges) {
            adj[e[0]] |= (1 << e[1]);
            adj[e[1]] |= (1 << e[0]);
        }

        int count = 0;
        for (int mask = 1; mask < (1 << n); mask++) {
            int sum = 0;
            for (int i = 0; i < n; i++) {
                if ((mask & (1 << i)) != 0) sum += nums[i];
            }
            if ((sum & 1) != 0) continue;

            int start = Integer.numberOfTrailingZeros(mask);
            int visited = 1 << start;
            Deque<Integer> q = new ArrayDeque<>();
            q.offer(start);
            while (!q.isEmpty()) {
                int node = q.poll();
                int frontier = adj[node] & mask & ~visited;
                while (frontier != 0) {
                    int next = Integer.numberOfTrailingZeros(frontier);
                    visited |= (1 << next);
                    q.offer(next);
                    frontier &= frontier - 1;
                }
            }

            if (visited == mask) count++;
        }
        return count;
    }
}
```

---

#### Lessons

- **Constraint-first reading.** `n ≤ 13` instantly screamed "subset enumeration." Brute force math (`2^n × n²`) was done upfront and confirmed feasibility before writing a single line. This is the right discipline.
- **Bitmask is a representation, not an algorithm.** It's just a way of encoding a set as an integer so that set ops become bit ops. Once you stop reading the integer as decimal and start reading it as "which bits are set," the rest is mechanical.
- **Bitmask signal:** `n ≤ 20-22` + "iterate all subsets" or "state = which elements are picked" is the trigger to reach for it.
- **Bitmask is the gateway to bitmask DP.** Subsets-as-array-indices unlocks problems like TSP. Worth investing in the fluency now.
- **Implementation discipline:** reference-vs-copy, indices-vs-values, dimension mismatch — all caught only by tracing examples. The 5-step ritual (especially "trace 1-2 given examples mentally" before coding) would have caught most of these. Drill that.

### #3 — Minimum Operations to Sort String

| Field | Value |
|-------|-------|
| Date | 2026-05-19 |
| Link | — |
| Rating | 1860 |
| AC | N (hinted) |
| Time | hinted |
| Pattern | Greedy / String — unsorted window + first/last occurrence of min/max |
| Revision due | 2026-06-02 |

---

#### Problem

Given a string `s`, each operation lets you sort any non-entire substring (non-descending). Return the minimum operations to sort `s`, or `-1` if impossible.

---

#### User's approach and the bug

User correctly identified the answer is always 0 / 1 / 2 / 3 / -1 and built a case analysis around global min/max positions. The logic was:

- 0 → already sorted
- n=2 and not sorted → -1
- min at position 0 OR max at position n-1 → 1 op
- max at position 0 AND min at position n-1 → 3 ops
- else → 2 ops

**Bug:** The 3-op condition fired on `"bba"` (max=`'b'` at pos 0, min=`'a'` at pos 2), returning 3. Correct answer is 2:
1. Sort `[1..2]` = `"ba"` → `"ab"` → `"bab"`
2. Sort `[0..1]` = `"ba"` → `"ab"` → `"abb"` ✓

Root cause: `'b'` appears at BOTH positions 0 and 1. The extra copy at position 1 means you can push `'b'` to the end without touching position 0, so only 2 ops are needed.

---

#### The correct conditions

**1 op** is possible iff the "unsorted window" — the first-to-last position that differs from the globally sorted string — is NOT the full string. Because if the window is `[l..r]` with `l > 0` or `r < n-1`, sorting exactly `[l..r]` sorts everything.

**3 ops** are needed iff:
- The unsorted window IS the full string `[0, n-1]`
- AND `maxChar` appears ONLY at position 0 (no copy in `[1..n-1]`)
- AND `minChar` appears ONLY at position `n-1` (no copy in `[0..n-2]`)

Why these conditions imply 3: to put `maxChar` at position `n-1` via a suffix sort, `maxChar` must be inside the sorted range. If it only exists at position 0, you need `i=0` as the start, meaning you'd have to sort the full string (forbidden). Same logic for `minChar`. Neither "end" can be fixed without the full string, so each requires a separate op, plus a third op to clean up the middle.

Why these conditions guarantee only 2 otherwise: if `maxChar` has a copy at any position `p ∈ [1..n-1]`, do op1 = sort `[p..n-1]` → `maxChar` lands at position `n-1`. Then op2 = sort `[0..n-2]` → everything else sorts into place. Analogous argument for `minChar`.

---

#### Corrected solution

```java
import java.util.Arrays;

class Solution {
    public int minOperations(String s) {
        int n = s.length();

        char[] sorted = s.toCharArray();
        Arrays.sort(sorted);

        int l = 0, r = n - 1;
        while (l < n && s.charAt(l) == sorted[l]) l++;
        while (r >= 0 && s.charAt(r) == sorted[r]) r--;

        if (l > r) return 0;               // already sorted
        if (n == 2) return -1;             // only single-char ops possible
        if (l > 0 || r < n - 1) return 1; // unsorted window is a proper substring

        // Full window [0, n-1]: check 3-op condition
        char minChar = sorted[0];
        char maxChar = sorted[n - 1];
        if (s.lastIndexOf(maxChar) == 0 && s.indexOf(minChar) == n - 1) return 3;

        return 2;
    }
}
```

---

#### Lessons

- **Duplicate characters break "position of global min/max" logic.** The naive check `max == s.charAt(0)` is true whenever *any* occurrence of max is at 0 — it says nothing about whether other copies exist. Always ask: "does this character appear anywhere else?"
- **The correct 3-op condition is about uniqueness, not presence.** `lastIndexOf(maxChar) == 0` means max exists ONLY at 0. `indexOf(minChar) == n-1` means min exists ONLY at n-1. Both conditions together mean neither end can be fixed without the full string.
- **Unsorted window = compare s to sorted(s), find first/last mismatch.** Cleaner and more general than hand-rolled position checks. Works regardless of duplicates.
- **AC with hint — need cold re-solve.** Schedule a clean attempt without looking at the solution.
